## Build and Deploy

```bash
# Build without switching, then review what would change
nixos-rebuild build --flake .#hodur
nvd diff /run/current-system ./result

# Rebuild and switch (human-run; activation needs root)
sudo nixos-rebuild switch --flake .#hodur

# Evaluate every output without building
nix flake check

# Format
nix fmt

# Update flake inputs
nix flake update
nix flake update <input-name>   # single input
```

`nixos-rebuild build` does not need root — it goes through the nix daemon.
Sandboxed sessions should build, `nvd diff`, and commit; a human reviews the
diff and runs `switch`.

## Architecture

Flake-parts + import-tree. Every `.nix` file under `modules/` is a
**flake-parts module**, discovered automatically — there are no import lists to
maintain. Adding a file is enough to add a module.

```
flake.nix                       # inputs only; delegates to import-tree ./modules
modules/
  parts.nix                     # systems, formatter, devShell, home-manager flakeModule
  features/                     # one file per feature
  hosts/<name>/
    default.nix                 # flake.nixosConfigurations.<name>
    configuration.nix           # flake.nixosModules.<name>  (host composition)
    home.nix                    # flake.homeModules.<name>
    _hardware.nix               # generated by nixos-generate-config
config/niri/config.kdl          # shared niri config
config/niri/hosts/<name>.kdl    # per-host niri overrides
```

### Key patterns

**Features are named, not path-imported.** A feature file assigns to
`flake.nixosModules.<name>` and/or `flake.homeModules.<name>`. Hosts compose
them by name (`imports = with self.nixosModules; [ niri battery ]`), so files
can be moved or renamed freely.

**One file spans both classes.** A feature with system *and* home-manager parts
declares both in the same file — see `modules/features/niri.nix`. Do not split
a feature across two trees.

**Optional features are `mkEnableOption` gated**, not import-gated, when they
carry host-specific settings (`custom.windowsBoot`, `custom.rebootToWindows`).
Custom options live under `custom.*` — never squat upstream namespaces.

**`import-tree` skips any path containing `/_`.** That is how `_hardware.nix`
stays a plain NixOS module that `nixos-generate-config` can regenerate
verbatim. Use the same trick for work in progress: an unfinished `.nix` under
`modules/` otherwise breaks evaluation for the whole flake.

**niri config is an out-of-store symlink** (`mkOutOfStoreSymlink`) so it can be
edited and reloaded without a rebuild. `config.kdl` is shared and ends with
`include optional=true "host.kdl"`; the per-host file is symlinked to
`host.kdl` based on `osConfig.networking.hostName`. This assumes home-manager
runs as a NixOS module (it reads `osConfig`). The repo is expected at
`~/nixos`.

**Home-manager is a NixOS module**, wired up by
`modules/features/home-manager.nix`; hosts set
`home-manager.users.tyler = self.homeModules.<host>`.

### Adding a host

1. `modules/hosts/<name>/default.nix` — `flake.nixosConfigurations.<name>`
2. `modules/hosts/<name>/configuration.nix` — compose features, set
   `networking.hostName` and its own `system.stateVersion`
3. `modules/hosts/<name>/home.nix` — compose home features
4. `modules/hosts/<name>/_hardware.nix` — from `nixos-generate-config`
5. `config/niri/hosts/<name>.kdl` if the host runs niri

`system.stateVersion` is per-host and must never be moved into a shared
feature — it records the release a machine was installed at.

## Hosts

- **hodur** — Intel laptop. Dual-boots Windows on a separate ESP; the Windows
  bootloader is mirrored into the NixOS ESP (`custom.windowsBoot`) so the other
  user of this machine gets a cold-boot menu.
- **uller** — desktop, not yet added. RTX 5070 Ti (Blackwell: open kernel
  modules are mandatory), dual-boots Windows 11 with Secure Boot enforced for
  Battlefield 6's Javelin anti-cheat, which requires lanzaboote on the NixOS
  side. Gets `custom.rebootToWindows` and its own ESP, so no bootloader
  mirroring.
